# Specialized Reconstruction Runner Inventory

This inventory records why the remaining non-table runners cannot all be
collapsed into the ordinary simulated-projection workflow. Keep these
boundaries explicit while their reusable pieces move into `dfr`.

| Runner | Observation source | Camera behavior | Current entry point | Migration boundary |
|---|---|---|---|---|
| `run_scenarios_angle_sweep.py` | Projections simulated from a canonical named dataset | Encircling cameras for the ordinary path; constructed two-camera baseline angles for sensitivity studies | Required study subcommand; `reconstruct` uses `ScenarioRunSpec` | Move angle construction, convergence traces, cached density grids, and sweep result types into package analysis modules before deleting the retained legacy ordinary-loop body. |
| `run_scenarios_flock.py` | Two external detection CSVs plus a MATLAB `xyzTensorValid` trajectory | Two calibrated cameras with unequal intrinsics and MATLAB extrinsics | Required study subcommand; primary `run` requires explicit input paths | Add a typed external-observation reconstruction API that accepts per-camera point sets and asymmetric camera intrinsics. Do not replace measured detections with simulated projections. |
| `run_scenarios_ue4.py` | Thresholded centroids from three external image sequences | Per-frame UE4 rotation/translation matrices and `CameraStateUE4` | Explicit `--image-roots` and `--project-root` | Add time-varying camera systems and an image/detection provider contract before moving the numerical loop. Do not coerce UE4 transforms into the static encircling-camera path. |

## Safety and output status

- Importing these modules no longer launches a CUDA experiment or creates a
  root log file.
- Every executable path requires an explicit command/action.
- The ordinary angle reconstruction now uses managed package artifacts when
  `IS_LOGGING` is enabled.
- Flock and UE4 numerical loops still contain legacy scenario-log or
  interactive plotting behavior. They are explicit legacy specializations,
  not yet supported managed workflows.
- Their next shared package abstraction should be an observation frame with
  ground-truth positions, one 2D point set per camera, and camera-system
  provenance. That contract can feed the existing reconstructor without
  pretending all observations were generated by `simulate_vision`.
